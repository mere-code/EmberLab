# EmberLab · 火借万物

一个计划使用 **Devin + Godot 4** 开发的像素横版独立游戏，以及用于验证核心交互的物理实验场。

玩家是一团火，没有固定的身体，需要借助环境生存和前进：**借木蓄热、迎水弹跳、展焰乘风、化作余烬穿越真空**。核心操作是“按住收拢，松开展焰”，让同一个障碍在不同状态下产生不同结果。

## 为什么使用 Devin

我计划使用 Devin 额度，将玩法构想变成可运行、可回放、可验证的 Godot 原型。Devin 将负责搭建场景、编写角色和环境交互、运行自动验收、记录失败并迭代参数；我负责试玩和判断手感。

第一阶段重点验证“水滴弹跳 + 风场”：建立统一的参数配置、固定物理步、输入录制与回放，再比较不同弹跳力度下的落点、热量消耗和操作容错窗口。游戏运行时由本地规则计算物理，Devin 在开发阶段执行代码与测试迭代。

**本仓库目前处于项目初始化阶段。尚未使用 Devin 完成开发，尚无玩法或物理测试通过的声明。**

## 核心机制

| 环境 | 展焰 | 收拢 |
| --- | --- | --- |
| 水滴 | 受到浇灭伤害 | 热量足够时消耗热量，触发蒸汽弹跳 |
| 强风 | 受风明显，可借上升气流飞起 | 降低受风影响，便于脱离气流和落地 |
| 易燃木材（后续阶段） | 点燃并蔓延 | 钻入蓄热，再破木而出 |
| 真空（后续阶段） | 外焰消失 | 化为短暂余烬，借惯性穿越 |

以上是游戏化规则，不是真实燃烧或流体模拟。

## 打开项目

目标环境为 Godot 4.x 稳定版、GDScript、Compatibility 渲染器。导入根目录的 `project.godot`，运行后应显示初始化状态页；当前尚未通过引擎启动验证，准确版本由 Devin 首次运行时记录。

第一阶段开发完成后，计划通过下面的命令运行验收（**当前脚本尚未实现**）：

```sh
bash tools/physics_lab/run_tests.sh
```

## 第一阶段完成标准

- 可操作的灰盒关卡，包含移动、跳跃、收拢、展焰、水滴和风场。
- 可配置的热量、风加速度与弹跳力度，所有公式使用同一份配置。
- 自动测试覆盖阈值、重复接触、角色运动、熄灭与重置。
- 固定物理步回放，以及实际执行生成的验收报告和参数扫描结果。
- 无图形环境或未执行的检查如实标记，不能当作通过。

后续再扩展木材燃烧、余烬穿越和像素视觉表现。
